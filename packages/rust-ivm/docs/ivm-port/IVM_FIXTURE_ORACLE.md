# IVM Fixture Oracle — status & divergences (Extraction #1)

## What the oracle is
`.input.json` (tables + ast + pushes) → **TS engine** (`agentic/oracle/ts-runner.mjs`)
produces `.expected.json` → **Rust engine** replays (`src/replay.rs`) and must
match byte-for-byte after canonicalization. Expected output is *only* ever
generated by the TS oracle, never hand-written.

Suite: `rust-ivm/tests/fixture_replay_test.rs` scans `agentic/fixtures/*.input.json`
(must all pass). `agentic/fixtures/regressions/` holds pending divergences and is
**not** scanned by the must-pass test.

## Coverage delivered this pass
- **Before:** 61 curated fixtures (exists.fetch, filter, join, join.push,
  join-utils, select, take.fetch). Push protocol for the hard operators
  (flipped-join, exists, cap, take) had **zero** coverage.
- **After:** **182 must-pass fixtures** (+121). Every `runPushTest`/`runFetchTest`
  in the push suite is now captured.

### New capture tooling (reusable)
- `agentic/oracle/capture-loader.mjs` — ESM loader that stubs `vitest`
  (describe/test/it/suite/each/for run immediately, expect is a no-op) and
  replaces `test/fetch-and-push-tests.ts` so `runPushTest`/`runFetchTest`
  serialize their **resolved runtime args** to `<name>.input.json`.
- `agentic/oracle/capture.mjs` — driver: `node --experimental-strip-types
  agentic/oracle/capture.mjs <test.ts>... --out <dir>`.
- Pipeline to add any new test file:
  1. `capture.mjs <file.test.ts>` → input.json fixtures
  2. `ts-runner.mjs <each input.json>` → expected.json (0 build errors = faithful)
  3. replay; passing → `fixtures/`, diverging → `fixtures/regressions/`.

Captured counts: take-push 51, flipped-join-push 46, exists-push 25, cap-push 17,
exists-flip-push 13, take-push-child 2, flipped-join-more-fetch 1.

## Divergences found (34 quarantined in regressions/)
The oracle immediately caught **34 genuine Rust-vs-TS divergences** in the newly
covered push paths (121/154 push fixtures pass; 0 panics). Four clusters — these
are candidate port-fix tasks, in priority order:

### cap-push (10) — Cap child-change handling
`child add below limit forwarded`, `child edit of tracked pk`, `child edit
changes pk / updates tracked set`, `child remove (with/without refill)`, `child
remove of last row → parent retraction`, compound-partition & compound-pk edit/
remove, unordered-overlay-in-join child remove. → Cap's `child`-change path and
tracked-pk-set maintenance diverge from TS.

### exists-push (10) — Exists child 0↔1 transitions
`child add resulting in 1 child pushed` / `→ parent add`, `child remove resulting
in 0 children` / `→ parent remove`, `child edit is pushed`, `child edit changes
correlation`, and the NOT-EXISTS mirrors. → the Exists operator's parent
add/remove on the empty↔non-empty boundary diverges.

### flipped-join (6) — edit-assignee cardinality transitions
`edit assignee none↔one↔many` (all four transitions) + `chunked path runs during
downstream refresh` (×2). → FlippedJoin edit handling across cardinality changes
and the chunked-fetch-during-refresh path.

### take-push (6) — remove at start of window
`remove row at start (no row after / with row after / limit-2)`, `remove < limit
remove row at start`, `edit changing partition value first→second`. → Take's
remove-at-window-start refill.

## Harness bug fixed
`assert_matches` (replay.rs) printed the `expected`/`actual` labels **swapped**
(it destructured `diff_path(actual, expected)`'s argument-ordered tuple with the
labels reversed). Every genuine divergence read backwards. Fixed.

## Build-hygiene note
The initial run showed a phantom "42 diverged" that vanished on clean rebuild:
an in-progress `Box<dyn Fn> → Rc<dyn Fn>` comparator refactor in the working tree
left three call sites (`flipped_join.rs:182/184`, `union_fan_in.rs:207`) passing
`Box`, so the lib didn't compile from source — a stale `.rlib` masked it. Those
three sites were completed to `Rc`. **Recommendation:** CI should `cargo clean -p
rust-ivm` before the fixture suite so a stale build can't hide a real divergence.

## Not covered (by design)
`push-accumulated.test.ts` (25) — documented in `fixtures/push-accumulated.SKIPPED.md`
as unit tests of internal functions (`pushAccumulatedChanges`,
`mergeRelationships`, `makeAddEmptyRelationships`) that the pipeline+source-push
fixture schema cannot express. These need direct Rust unit tests, not fixtures.
